Editorial summary

Adding Skills can change how an agent uses its existing permissions, even when those permissions and the existing Skills remain unchanged. This issue pairs research on Skill composition with a proposal for messages that carry evidence, then asks how both should be checked at the point of action. A signed or historical record is not enough when the relevant state may have changed. The evaluation papers examine two further sources of error: an interface change can disrupt a trained policy, and scanned-document tasks can fail between search, page retrieval and number reading. The serving readings extend the analysis to whole sessions, where tool delays, cache retention and available KV capacity interact. More capacity does not necessarily make each token faster, and the scheduling study retains a case where latency worsened. These findings are author reports rather than LATENTX replications. PCM is a research proposal, not an MCP standard. Practical trials should preserve authorization, test interface migrations and compare serving behavior under matched workloads.

Four judgments for platform architects

  1. Treat Skill additions as system changes. Composition changes how existing permissions are exercised. Review downstream use of artifacts, approval signals, and destinations.
  2. Bind assertions to observable evidence. An authenticated agent's message still needs verification. A historical success receipt also needs a freshness check before a consequential action.
  3. Version the model and its interface together. Field order, tool encoding, and execution rules are part of the deployed system. Compare frozen behavior separately from equal-budget adaptation.
  4. Optimize the whole session. Tool latency, cache retention, and decode capacity interact. Lower mean latency, peak throughput, and more KV capacity are distinct objectives.

These are editorial judgments, not findings independently established by LATENTX.

Theme selections

1. CoSA: authorization can disappear between individually admitted Skills

Read first · v1, October 26. CoSA: The Conflict of Skills Attack in Real-World LLM Agent Ecosystems.

In the CoSA evaluation, across 288 controlled tasks, five models and three harnesses, adding at most 5% to each Skill pool raises violations from 35.02% to 58.45%. Existing permissions and Skills stay fixed. The OpenClaw recruiting guard experiment reduces violations from 65.28% to 6.67%, with benign completion moving from 66.67% to 65.00%.

Preserve purpose and authorization through artifact handoffs. This is a fixed evaluation grid, not a production incident probability; defense evidence covers a narrower domain and harness.

2. PCM: evidence-bearing messages need an independent trust boundary

High priority · v1, October 29 · research proposal, not an MCP standard. PCM: A Proof-Carrying Message Protocol for Verifiable Multi-Agent Communication.

The proposal uses signed append-only records to support claims and grants rooted in human authorization that can only be narrowed. Agent self-reports cannot establish proof. In the authors' 926-message test, 10 false claims are accepted, all using stale evidence.

Verify action receipts against records the agent cannot alter and recheck current state before execution. Honest signers and attesting executors are assumptions; evidence does not prove freshness, completeness, or benign intent. Protocol baselines include modeled implementations, not audited production deployments.

3. A fixed-model harness comparison can reject a useful interface

High priority · first submitted October 27; v2 October 28. Your Policy Is Secretly a Harness: The Decision Geometry of Agent Interfaces.

The harness paper shows that under KL-regularized control, deployed return separates into harness ceiling and policy mismatch. In a Qwen3.5-2B MiniWoB++ study, reversing observation fields drops trained success from 85.0% to 19.2% despite unchanged optimal decisions.

Pin serialization and test both immediate migration and equal-budget adaptation. Controlled tasks support the mechanism; using a stronger teacher to estimate a coding harness's optimum remains a proxy, not a universal capability ceiling.

4. TreasuryQA: test the search-to-scan path, including wrong digits

High priority · v1, October 28 UTC. TreasuryQA Bench: Can AI Agents Work an Archive of Scanned Financial Records?.

70 questions over 1,435 scanned publications use a Dropbox twin, MCP and OCR. Ten pinned model–harness pairs attempt each task three times at high reasoning effort. Claude Opus 5.5 in Claude Code reaches 64.8% pass@1; adjacent rankings are not statistically significant after correction.

Retain page evidence and use numeric tolerance graders. Only three worked examples are public; most tasks remain private. Provider hardware and serving concurrency are not controlled, and listed model cost excludes OCR charges.

5. TAO: schedule tool readiness with cache value and placement

High priority · v1, October 27. TAO: Tool-Aware Joint Scheduling for LLM-Based Agentic Serving.

DeepSeek-V4 Flash on two nodes, each with 4×H100, SWE-Lite and 64 workers reports 26.8% lower mean task latency, 36.3% lower mean TTFT and 29.5% more decode throughput against the best baseline per metric. Baselines include Dynamo, round-robin/cache-aware vLLM and ThunderAgent; observed node cache credit decays with age.

Measure post-tool return delay alongside total task time. Maxima are not universal; Qwen3-32B SWE-verified at 128 workers has 2.5% worse latency than the best baseline. Cache policy and predictor error must accompany comparisons.

6. Mistral Large 4: KV capacity is not decode speed

High priority · maintainer page dated October 29; earliest public timestamp not independently established. Day 0 support for Mistral Large 4 on vLLM.

On 8×GB300, NVFP4, TP8 versus TP8+DCP8, no speculative decoding, 8k–60k inputs and up to 128 concurrent requests, DCP decodes 16–28% slower per token. KV capacity rises from 3.60M to 28.76M tokens at memory utilization 0.85; this is capacity, not a throughput multiplier.

Enable DCP when KV residency constrains sessions. Matching prefix-cache state is not established for that comparison; P/D results explicitly disable prefix caching. Do not combine these separate experiments.

Architecture decisions and tradeoffs

Decision Benefit Cost and acceptance evidence
Check authorization at the side-effect boundary Preserves action, target and purpose across Skills Extra checks and false blocks; retain allowed controls
Store attestations where agents cannot alter them Makes reported actions verifiable Signer operations and freshness checks remain necessary
Version model, prompts, schema and harness as one release Makes regressions attributable More evaluation cells; separate adaptation budgets
Add tool-aware scheduling before buying capacity Can reduce idle time and post-tool delay Predictor error, planner overhead and fairness need observation
Shard KV only when capacity binds Supports longer resident sessions Collectives add latency; compare the same workload/cache state

PoC and acceptance metrics

The following are editorial pilot targets, not published results or permission to deploy:

  • Composition test: run the same 100 synthetic business requests before and after a Skill addition. Require zero unauthorized writes or exports and no more than a 2 percentage-point loss in allowed completion; inspect every blocked control.
  • Evidence test: replay fabricated, stale, cross-tenant and duplicate receipts, including after restart. Require zero consequential actions from invalid evidence and a fresh read before each state-dependent action.
  • Interface migration: freeze checkpoint and task set, then change one interface element at a time. Record valid completion, correctness, tool errors, tokens and cost. Set a 2 percentage-point non-inferiority margin with a task-bootstrap interval; test adaptation separately with equal budgets.
  • Serving test: sweep 16/32/64 sessions with fixed model, precision, hardware, input/output lengths and tool-delay distribution. Compare cold and warm caches separately. Record p50/p95 TTFT, post-tool delay, total task time, throughput, cache hit rate, failures and per-session fairness. Promote only if p95 task latency improves at least 10% without more failures or a throughput loss above 5%.
