We don’t have public documentation that explains why Shared Projects aren’t supported in the new macOS desktop app, or any public roadmap/timeframe for when they might be; the published guidance today is that shared projects are available on web and mobile apps (and the macOS release notes also note that projects must be created on web first).

For the collaboration scenario in a ChatGPT Business workspace, the documented/supported approach is:

  • Create the project (and share it) on the web (or mobile), then use Share to invite coworkers with chat or edit access.
  • Move eligible existing ChatGPT chats into that project using Move to project / drag-and-drop (when available). Note: chats created with a custom GPT can’t be moved into a project; if a chat isn’t eligible, you’ll need to start a new chat inside the project instead.
  • Re-add project instructions and upload/add sources in the shared project as needed (files added to a shared project are shared with all members).

Items that are not documented as transferable/preservable via a “conversion” from a local desktop project include local-folder associations, and Codex projects/history (Codex remains a separate view and its history is separate from ChatGPT history). Also, shared projects are automatically set to project-only memory, and project-only memory notes that ChatGPT Work is not available in the project.

Shared Projects are currently not supported in the new ChatGPT desktop app. At this time, the supported way to access and collaborate in a Shared Project is through ChatGPT on the web or supported mobile apps using the same account and workspace.

For project migration, the behavior depends on how the project was created. A desktop-created local-only project cannot be directly converted or automatically migrated into a Shared Project through ChatGPT web. In that case, you would need to create a web-accessible ChatGPT Project and manually transfer the relevant content before sharing it. If the desktop-created project is already a cloud-synced ChatGPT Project, you can open it on ChatGPT web and use the Share option there. OpenAI’s Projects documentation provides the current guidance for creating, organizing, and sharing projects: Projects in ChatGPT

When moving work manually, eligible existing chats can be moved into a project where that option is available. Project instructions and files can be added to the destination project, but local-only desktop associations do not automatically transfer as part of a Shared Project migration. Shared Projects use project-only memory, which keeps the project context isolated to that project. For more information about how Projects and shared access work, please refer to the Projects in ChatGPT article above.

Codex history remains separate from ChatGPT history, and local Codex or desktop-only project state should not be expected to migrate automatically into a Shared Project. For the current relationship between ChatGPT Work, Codex, and project workflows, please refer to: ChatGPT Work and Codex

For collaboration in a ChatGPT Business workspace, the recommended approach is generally to use a web-accessible Shared Project as the common collaboration space, with appropriate Chat or Edit permissions for members. You can then organize separate chats within that project by task or workstream and add the relevant shared files, sources, and project instructions there. Where external sources such as GitHub or Google Drive are used, access and availability depend on the connected app permissions and workspace configuration.

We do not currently have a public roadmap or timeframe to share for Shared Project support in the new desktop app, so we cannot confirm when that capability may become available.

3. OpenAI 的主要观点

  1. 当前访问路径： 新版桌面应用目前不支持 Shared Projects，协作应使用同账号、同工作区的 Web 或受支持的移动端。E1、E5。
  2. 迁移先识别项目类型： 本地专属项目不能通过 Web 直接转换或自动迁移；需要手工整理内容。已经云端同步的 ChatGPT Project 可以在 Web 打开并使用 Share。E5。
  3. 内容与执行状态有不同迁移边界： 合格聊天可在界面提供选项时移动，指令和文件可添加；本地文件夹关联与本地 Codex 状态不会自动迁移，Codex 历史独立于 ChatGPT 历史。E5。
  4. 团队结构： Business 工作区以 Web 可访问的 Shared Project 作为共同空间，成员采用 Chat/Edit 权限，并按任务组织独立聊天。外部来源可用性受连接应用与工作区权限影响。E5。
  5. 仍未解释的部分： 客服没有给出不支持的具体原因；E5 明确表示没有可分享的公开路线图或时间表，也没有提供 Work 历史的完整迁移步骤。E2、E4、E5。

E3 关于 project-only memory 下 Work 不可用的说法有当前 Projects in ChatGPT 文档依据，但 E5 没有逐项确认它。E3 声称“macOS 项目必须先在 Web 创建”，在其所引的当前 macOS release notes 中未找到对应说明；E5 反而明确允许已云同步的桌面创建项目在 Web 共享。因此，这条 AI 表述不应作为所有项目的迁移前提。

4. 简要结论

共享协作可以在 Web 建立。迁移时先区分云同步 ChatGPT Project 与本地专属项目：前者直接在 Web 共享，后者手工转移必要内容，并保留原始执行环境和历史。当前客服回复解决了可采用的路径，产品原因、未来桌面支持时间及 Work 历史迁移细节仍未明确。
